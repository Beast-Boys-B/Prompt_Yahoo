# Yahoo_Prompt

> 누구나 쉽게 AI를 활용할 수 있도록 — 프롬프트 작성 도우미

## 문제 정의

AI 사용자층은 다양한 연령대로 계속 늘고 있지만, AI 비전공자가 작성한 프롬프트는 의도한 산출물을 뽑아내지 못하는 경우가 많습니다. 특히 40대 이상 고령층에서는 프롬프트 입력 자체를 어려워하는 경우가 흔합니다.

현재 이 문제의 해법은 사실상 두 가지뿐입니다.
1. 원하는 답이 나올 때까지 AI와 계속 씨름하기
2. 본인이 프롬프트 엔지니어링을 따로 공부해서 활용하기

**Yahoo_Prompt**는 이 사이의 빈 자리를 채우는 도구입니다. 사용자가 자연어로 편하게 입력하면, 규칙 기반으로 신호를 추출해 AI가 더 잘 알아듣는 프롬프트로 자동 정리해줍니다.

## 타겟 사용자

ChatGPT·Gemini 등 범용 AI를 업무·일상에 활용하려는, 아직 프롬프트 작성에 익숙하지 않은 사용자 (특히 40대 이상, 비전공자)

## 핵심 방향

- **규칙 기반 (LLM 미탑재)**: 자연어 입력 → 키워드 매칭으로 신호 추출 → 지정 템플릿에 매핑. 구현 안정성을 최우선으로 함.
- **투명한 자동화**: 추출된 신호는 조용히 자동 적용되지 않고, 토글/선택 UI에 "미리 선택된 상태"로만 반영됩니다. 사용자는 항상 결과를 확인하고 직접 수정할 수 있습니다. 확인 화면에서는 **자동 감지된 값**(브랜드 컬러+스파클 배지)과 **기본값으로 채워진 값**(회색 테두리 배지)을 시각적으로 구분해서 보여줍니다.
- **공통 축 없음**: 모든 카테고리가 공유하는 전역 설정(모드, 길이 등)은 두지 않습니다. 각 카테고리는 오직 **전용 축**만으로 구성됩니다.
- **1차 목표**: 웹페이지 → 이후 Chrome 확장 프로그램(오버레이 형태)으로 확장 예정

## 처리 흐름

```
템플릿 선택 → 자연어 입력 → 신호 추출 → 토글 사전 선택
→ 사용자 확인/수정 → 프롬프트 생성 → 결과 확인 → 완료
```

결과 확인 단계에서 "아니오"를 선택해도 자연어를 다시 쓸 필요 없이, 그 화면 안에서 토글만 바로 고쳐 재생성할 수 있습니다.

## 카테고리 (5개, 4인 분담)

| 카테고리 | 설명 | 출력 형식 | 담당 | 상태 |
|---|---|---|---|---|
| 작성 | 이메일·메신저·회의록·보고서·기획서 | 역할지정형 | 담당자 조연익 | ✅ 확정 |
| 개인상담 | 고민·감정·인간관계 조언 | 역할지정형 | 담당자 이재성 | ⏳ 축1(관계유형)·축4(상담주제) 말투 우선순위 결정 대기 |
| 의료질문/문진 | 증상 확인·진료 준비 | 역할지정형 | 담당자 우석민 | ✅ 확정 |
| 여행계획 | 일정·코스 짜기 | 역할지정형 | 담당자 김동윤 | ✅ 확정 |
| AI 사진생성 | 이미지 생성 프롬프트 만들기 | **태그나열형** | 담당자 조연익 (작성과 동일) | ✅ 확정 |

> AI 사진생성은 최종 결과물이 대화형 문장이 아니라 이미지 생성 AI용 태그 나열 프롬프트라서, 다른 4개 카테고리와 출력 형식이 다릅니다. UI상에서도 이 카테고리만 카드에 별도 배지, 결과 화면에 별도 안내 문구를 사용합니다.

각 카테고리의 전용 축·키워드 사전은 [`/schemas`](./schemas) 폴더를 참고하세요. 스키마 작성 방법은 [`CONTRIBUTING.md`](./CONTRIBUTING.md)에 정리되어 있습니다.

## 카테고리 설정 스키마

```
카테고리 설정 = {
  이름,
  출력_형식: "역할지정형" | "태그나열형",
  전용_축: [
    { 축_이름, 선택지(2택 이상 가능), 키워드사전(선택지별), 기본값 },
    ...
  ],
  고정_규칙: [
    { 조건: "항상" | "축_이름=값", 문구: "..." },
    ...
  ]
}
```

- **전용 축만 사용**: 카테고리마다 0개~N개 자유롭게 구성합니다. 모든 카테고리가 공유하는 전역 축(공통 축)은 두지 않습니다 — 카테고리별로 실제 의미 있는 축만 정의합니다. 다만 카테고리당 3~4개를 넘어가면 확인 화면 토글이 많아져 UX 부담이 커지므로, 디자인 단에서 아코디언(접기/펼치기) 등으로 밀도를 조절합니다.
- **고정 규칙**: "항상 적용"과 "특정 축이 특정 값일 때만 적용"을 하나의 배열 형식으로 통일해서 표현합니다. (예: 의료질문의 응급 안내문구는 `조건: 항상`, 작성의 존댓말 권장은 `조건: 대상=상급자_외부인`)
- 선택지가 아예 다른 특수 케이스(예: 학술 카테고리의 "논문분석" 모드)는 기존 축에 억지로 포함시키지 않고 별도 카테고리로 분리합니다.

### 자유 슬롯(지명, 고유명사 등)에 대한 원칙

목적지·이름 등 정해진 키워드 리스트로 판별할 수 없는 자유 슬롯은 규칙 엔진으로 감지하지 않습니다. 대신 자연어 입력창의 placeholder 문구로 자연스럽게 유도합니다. (예: 여행계획 카테고리의 "여행지와 함께 편하게 적어주세요" 안내)

## 결과 확인 화면 UX

- 사용자가 쓴 원문은 그대로 두고, 시스템이 자동 삽입한 지시문 부분만 하이라이트해서 재검토 부담을 줄입니다.
- "내가 쓴 내용 / 자동 추가된 지시문"을 필터로 나눠 볼 수 있습니다.
- 신호 추출로 자동 감지된 값과, 신호가 없어 기본값으로 떨어진 값은 배지 스타일로 구분됩니다.

## 디자인 (Figma Make)

3~4라운드에 걸쳐 피드백 반영 중입니다.
- 톤 통일(브랜드 컬러 반영), 여백/레이아웃, 카드 크기, 스텝 인디케이터 개선
- 카테고리 5개 + 3·2 그리드 배치, 아이콘/서브 라벨 정리
- "AI 프롬프트 도구" 정체성 강화 (터미널 기호, 비교 예시 카드, 자동감지 스파클 아이콘)
- 자동감지/기본값 배지 구분, 토글 3~4개 카테고리의 확인 화면 밀도 개선(아코디언 등)
